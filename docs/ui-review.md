# UI/UX review

The pages were busy because routine context, navigation, and exceptions competed at the same visual level. The changes prioritize the record, its actionable state, and the next action. Supporting definitions and metadata are available on demand.

| Area | Review finding | Implemented change |
| --- | --- | --- |
| Navigation | The sidebar always occupied its full width on desktop, and its footer contained unnecessary fleet/account controls and a driver-app preview. | A collapse/expand control switches between labeled navigation and an icon rail, with accessible tooltips and a saved preference. The footer controls and driver-preview screen/code are removed. Narrow tablet expansion overlays the workspace; mobile keeps its bottom navigation and More menu. |
| Sessions | Lifecycle counts appeared twice; origin and reason controls were always visible; rows repeated owner, cycle, lifecycle, and reason. The cleaned list lacked an overview of progress and current work. | One set of status tabs; origin/reason filter panel with active count and reset; one concise status; origin icons and activity tooltips. A compact overview adds weekly completion with a trend and the current review-reason mix with filter shortcuts. Full record context remains in the drawer and accessible row name. |
| Analytics | Repeated report scope and KPI definitions; long result labels; cramped chart legends and mobile labels. | One report scope, metric help icons, quieter charts, semantic tables, distinct result icons, and responsive chart geometry. Units, time windows, and chart summaries remain available. |
| Drivers | Histogram and three selectors dominated the list; duplicate attention control; repeated coaching/action metadata. Hiding the entire distribution removed useful fleet context, while coaching-by-group belonged on Groups. | Three compact panels: fleet safety mix, current coaching activity with completed history separated, and a driver improvement from the directory sample. The full histogram is optional. Search and Filters, the five-column directory, consistent statuses, and metadata tooltips remain. |
| Automation Centre | Repeated “review,” “decreasing,” and “increasing” labels below each number. | Clear numeric cells and a small priority icon; descriptive accessible row labels. |
| Automation Centre (follow-up) | The spotlight “Review” opened a rationale tray that duplicated Sessions and Drivers; the programs table had one lens and no origin split. | Review and the spotlight name open the driver’s record in Drivers; the rationale tray is removed. The table gains a Program/Group lens, Automated/Manual columns, and a “Needs review” label. |
| Analytics outcomes | Four tiles repeated Automation Centre figures; three parallel trend lines did not answer “before vs after.” | One headline, one readout, and a before → after paired-dot chart per program, group, or driver that follows the Outcome details lens. |
| Session footage | "Attach evidence" only raised a toast; clips existed as static text and could not be viewed or sent. | Footage filmstrip with an inline player in the session summary, a library of the driver’s other clips and unassigned clips with search, attach-to-reply chips, clip cards inside sent messages, and clip counts on session rows and the Automation Centre spotlight. Playback is a mock stage; assignment updates the in-memory pool. |
| Settings rules | Programs were a static table; event types, severity, trigger thresholds, and escalation could not be chosen, added, removed, or changed. | Safety event types (on/off, severity, events per cycle, video required, coaching path, add/remove) and when/then coaching rules (scope, condition, action, add/remove), all drafted and activated with the automation settings; the impact panel counts affected programs and the audit history records the change. Configuration persists locally. |
| Vocabulary & shared columns | Coaching state was named differently per page (System handling, Escalated, Attention, Manual, Coached, Monitoring) and the Programs, Groups, and Drivers tables each had their own columns and sources. | One vocabulary — Automated, One-on-one, Needs review, Completed, Archived, On track — across the stat band, tables, tabs, statuses, drawers, and analytics; Programs and Groups share the Automated · One-on-one · Needs review · Completed columns read from the session ledger, Drivers tabs and statuses use the same words, and Analytics Activity (KPIs, weekly bars with a One-on-one series, Program performance) reads the same four states from the ledger. The program and group drawers list the very session records the tables count (tabs Needs review · Automated · One-on-one · Completed), and a real period control (This week / Last 4 weeks / Last 8 weeks) in the Automation Centre header and inside the drawers moves the table, stat band, and drawer together. |
| Groups | Repeated program-count subtitles; excessively tall mobile cards; summary labels showed little of the underlying movement. Highest score repeated the table while coaching-by-group sat on Drivers. | Three overview panels: current automated assignments by group, most improved event-rate trend, and worsening event-rate trend. Concise rows, two-column mobile metrics, and accessible labels synchronized with counts remain. |
| Content | Identical requirements paragraphs on every card; decorative play control implied playback. | Requirements/version in help; title/category/duration remain visible; neutral film icon. |
| Settings | Saved state repeated draft/active/no-change explanations and disabled actions. | Saved draft panel collapses; editing reveals relevant actions; Preview and History stay available. |

Primary operational states remain visible: Replied, Overdue, Repeated, Blocked, In progress, Completed, and Archived. Icons supplement these labels. Help works on hover, keyboard focus, and tap, and dismisses with Escape. Filter panels have focus containment, Escape/backdrop dismissal, and return focus to their trigger.

Sessions, Drivers, and Groups use a shared compact overview between the page header and dataset toolbar. Its two or three panels stack on narrow screens. Fleet summaries stay stable under table filters; their filter shortcuts clear conflicting selections before showing the requested records. Shared chart behavior is in `dist/overview.js` and the placement rules are in `DESIGN_SYSTEM.md`.

Each panel identifies its scope. Sessions initially shows 128 of 142 automated assignments completed for the week of Aug 31 separately from the current 177-record ledger. Drivers keeps the 1,024-driver safety mix visible and the full histogram optional. Its coaching panel shows 5 automated and 2 manager-created one-on-one sessions in progress, with 130 completed shown separately under All recorded sessions. It does not mix current work with all-history origin totals. Its improvement highlight is Taylor Brooks, +7 points from 71 to 78, explicitly among the 14 directory records rather than the full fleet.

Groups now owns coaching-by-group: 48 North, 37 Local delivery, 31 East, and 26 West automated assignments for the week of Aug 31. The other two panels surface Local delivery's 29% event-rate improvement and North's 8% worsening over Jul 13–Aug 31, using events per 1,000 trips. Highest safety score remains in the comparison table. Workload counts describe assignments or sessions, not unique drivers.

Mobbin references inspected: [Twenty’s filter popover](https://mobbin.com/screens/c4089aab-6ec1-4507-b53f-19abd7dbf459) for optional controls and applied-filter visibility; [Fresha’s table](https://mobbin.com/screens/3b1a8630-7e3d-4e22-aa49-f38180943f60) for restrained row styling; [Asana’s task overview](https://mobbin.com/screens/eeef57df-99fe-478f-852f-8d52dd5e3360) for short Upcoming/Overdue/Completed tabs and a quiet weekly completed count. The Asana reference informed the decision to separate current coaching from completed history and keep the time scope visible. These informed the approach; the implementation retains Elevate’s visual identity.

Integration corrections restored the refinement stylesheet links after overlapping edits, removed an initialization error, made filter-panel actions visible, prevented tooltip Escape from clearing session search, released modal state during navigation, and removed shadows from closed drawers.

Overview checks cover stable fleet totals under filters, correct session-origin shortcuts, driver improvement selection, and group-detail focus restoration. Drivers URL search is restored before rows render, so reopening a filtered link shows matching results immediately. Completing a one-on-one session removes it from the in-progress count and adds it to the separate completed count.

Validation completed with syntax checks, all six existing contract tests, and the browser smoke check in `tests/browser-smoke.mjs`. Browser checks cover local asset loading, filters/reset/search, keyboard navigation, tooltips, detail drawers, analytics breakdowns, route recovery, and page overflow at 1440, 1024, 768, and 390 pixels. Additional manual browser checks cover Settings preview/history/discard and driver distribution/sorting. No JavaScript errors or page-level horizontal overflow were observed. Analytics tables intentionally scroll horizontally on narrow screens.

The prototype still uses mock data. Analytics has fixed reporting windows; its previous filter buttons only displayed placeholder toasts, so those were replaced with explicit scope labels. Driver population totals describe the fixture fleet while the directory contains 14 representative records. Existing export placeholder actions are outside this visual cleanup.

Shared placements, tokens, and interaction rules are now formalized in [DESIGN_SYSTEM.md](../DESIGN_SYSTEM.md), with matching `design-system.css` / `design-system.js` implementation and entry instructions for Codex and Claude. Sessions and Drivers use tabs → search → Filters in one dataset toolbar; Analytics uses tabs → scope below its page header. Browser assertions protect these placements.
