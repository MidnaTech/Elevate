## Summary

The nightly job: for every entitled tenant and every active programme, recompute **every day of the period that contains yesterday** (1–14 period-to-date rows per pair) from source through the shared `score_window()` component (ELEV-002, D17) and replace them in one transaction per (tenant, programme) — so a late-arriving event anywhere in the open period is reflected on the chart the next morning; refuse to write when incidents exist but no mileage does; notify admins about rules that matched nothing for 14 days; set the tenant-level liveness metric.

## Background

### What exists today (current architecture)

- Job entrypoint pattern: `backend/app/db/migrate_all.py:151–180` — argparse `main(argv)`, per-tenant try/except appending to a report, exit 1 if any failed.
- Structured log fields required: `tenant_id`, `stage`, …
- Metrics: `app.observability.metrics` gauges with labels limited to `ALLOWED_LABELS`; exporter `GAUGES` tuple is closed → new gauge names must be added there.
- Entitlement: `tenant_features` (`control_plane.py:122–130`), read via `flags.flag(tenant_id, "elevate.enabled", False)`.
- `tenant_connection(tenant_id)` = one transaction (`session.py:56`); `SET LOCAL` allowed.

### What this story does (the proposed change)

Creates `backend/app/elevate/jobs/score_daily.py` and the metric registrations. Writes only `elevate_driver_daily_scores` and `elevate_notifications`.

### Why we're making this change (per the decision log)

D8: daily rows are the chart. R1: *"if a tenant's Σ trips.distance_m for the period is 0 … refuse to write score rows at all rather than writing a fleet of `insufficient`."* R16: pinned `vendor_event_ref` can silently stop matching → nightly reconciliation notice.

## Requirements

### 4. Job contract

Entrypoint: `python -m app.elevate.jobs.score_daily [--tenant T] [--date YYYY-MM-DD]`; `--date` defaults to today UTC; the slice is every day of the period containing `date−1`. No lookback flag — D17: the whole open period is always rebuilt.

```python
async def run(*, tenant_id: str | None, run_date: date) -> Report
# one SliceResult per (tenant, programme, period_start): status completed | partial | failed | skipped_locked
# and rows_deleted / rows_written / errors; exit 1 only if any slice failed
```

Per (tenant, programme) — one `tenant_connection` = one transaction:

```
ps = period_start_for(run_date - 1, anchor); slice = [ps ... run_date-1]
async with tenant_connection(t) as conn:
    SET LOCAL statement_timeout = '300s'
    locked = pg_try_advisory_xact_lock(hashtext('elevate_dds:' || programme || ':' || ps))
    if not locked: status = 'skipped_locked'; return   # another run owns this slice
    version = effective_version_for(conn, programme, ps)
    for d in slice:
        since = max(ps 00:00Z, version.prospective_from 00:00Z, version.activated_at); until = d + 1 day 00:00Z
        for driver, ps_ in score_window(conn, version=version, since=since, until=until).items():
            rows.append(DailyRow(...))
    DELETE FROM elevate_driver_daily_scores WHERE programme_id = P AND period_start = ps  -- the whole open period
    INSERT rows (validated via shapes.RuleMaps before insert; score/miles via ELEV-001 quantize_*)
```

Denominator check (per tenant, before any programme write, over `[min period_start in slice, run_date)`):

```sql
SELECT (SELECT count(*) FROM elevate_scoring_events WHERE occurred_at >= :since AND occurred_at < :until AND driver_id IS NOT NULL) AS incidents,
       (SELECT coalesce(sum(distance_m),0) FROM trips WHERE driver_id IS NOT NULL AND started_at >= :since AND started_at < :until) AS metres;
```

If `incidents > 0 AND metres = 0` → skip all writes for the tenant; `log_event(..., "elevate.denominator_missing")`; gauge `elevate_denominator_missing{tenant_id}=1`; `notify.enqueue(admin, kind="denominator_missing", dedupe_key=f"denominator_missing:{t}:{run_date}")` for each `org_admin`. Otherwise gauge = 0.

Reconciliation (per tenant, after writes): for each active programme's current rules, `(vendor_id, vendor_event_ref)` with zero rows in `elevate_scoring_events` over the last 14 days **while** the tenant has ≥ 1 row for that `vendor_id` → `notify.enqueue(admin, kind="rule_unmatched", dedupe_key=f"rule_unmatched:{rule_id}:{iso_year}-W{iso_week}")`.

Metrics (tenant-only labels): `elevate_scoring_age_seconds{tenant_id}` set to 0 only when every active programme's slice is `completed`; `elevate_denominator_missing{tenant_id}`. Both added to `metrics.py` gauge registry and `exporter.GAUGES`.

Logs: every line `tenant_id`, `stage="elevate.score_daily"`, plus `programme_id`, `days`, `rows_written`, `duration_ms` where applicable.
