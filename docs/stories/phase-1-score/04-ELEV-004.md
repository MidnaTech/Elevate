## Summary

The service layer under the programme API: create/patch/replace-rules/replace-learning/archive/restore as functions on a tenant connection, each writing its `elevate_config_audit` row in the same transaction, freezing a new `elevate_programme_versions` row on every scoring-affecting change, filling `weight` from the severity label and `dedup_group` from the control-plane taxonomy — plus `effective_version_for()`, the one function the scoring jobs call to know which rules apply to a period.

## Background

### What exists today (current architecture)

- Tables from FOUNDATION-2/3.
- Taxonomy lookup: `vendor_event_mappings` (`control_plane.py:83–98`), PK `(vendor_id, vendor_event_ref, tenant_id)`, `tenant_id = ''` default rows; read through `get_control_plane_session()` (`backend/app/auth/scope.py:131`).
- Contract §02: severity prefill Low 1 · Medium 3 · High 5 · Critical 10, admin may override; rule reuse across programmes warned not blocked; only fleet admins change scoring settings; every score component records the configuration version used. §05: activating mid-period is prospective, no backfill; archive stops scoring immediately; restore resumes prospectively.

### What this story does (the proposed change)

Creates `backend/app/elevate/config/{service.py, versions.py, taxonomy.py, schemas.py}`. All functions take `conn: AsyncConnection` (tenant) and `actor_user_id`; API stories wrap them in `tenant_connection`.

### Why we're making this change (per the decision log)

D1 → `freeze_version()` on scoring-affecting change; `effective_version_for()` = latest with `created_at <= period_start`, else version 1 prospective from creation. D13 → `dedup_group` default from `event_type`. R4 → audit here, not `audit_log`. R16 → `rules_available()` is the only source of pickable refs.

## Acceptance Criteria (as recorded)

- AC1 — `create_programme` writes programme + rules + learning, one audit row (`programme`,`create`), one version row (1) equal to the live rows; `weight` prefilled from severity when omitted; `allowed_per_1000mi = 0` when omitted; `dedup_group` = mapping `event_type` when omitted.
- AC2 — Unmapped `(vendor_id, vendor_event_ref)` → `RuleNotMapped`, nothing written (including no audit row).
- AC3 — `replace_rules` on version 3 → version 4 frozen with `created_at = now()`; `patch_programme` of `name` only → no new version; of `threshold` → new version.
- AC4 — `effective_version_for(P, 2026-09-14)` with versions created 2026-09-01 (v1) and 2026-09-21 (v2) returns v1; for `2026-09-28` returns v2; for a programme created 2026-09-18 and period start 2026-09-14 returns v1 with `prospective_from = 2026-09-18`.
- AC5 — `rule_reuse_warnings` lists other active programmes sharing a rule; archived programmes excluded.
- AC6 — Every mutator leaves exactly one more `elevate_config_audit` row than before, with before/after populated for updates.
- AC7 — `archive_programme` sets `status = archived` and returns the count of that programme's open sessions; `restore_programme` sets `activated_at = now()` and freezes a new version.
- AC8 — Programme archived on day 3 of a period and restored on day 9: `effective_version_for(P, period_start).activated_at` is the day-9 timestamp; ELEV-002 `score_window` called with the clamped window scores incidents from day 9 on only.
